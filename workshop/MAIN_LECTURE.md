# 从一条录音开始：用飞书 + Codex 搭建你的第一个录音 Agent

适合人群：对 Agent 感兴趣，但还不知道怎么开始的小白

使用工具：飞书妙记、Codex、Recording Agent Starter

今天的目标：不学习终端，不背技术命令，只在 Codex 界面里完成一条由本人掌控、可以持续纠正的录音 Agent Loop。

---

## 课堂约定：你只和 Agent 对话

今天假定课前准备已经完成：需要的软件已经下载，Codex 已经可以使用。软件安装属于另一份预习手册，不占用课堂时间。

课堂里你不需要打开终端，也不需要复制代码。你只做三件事：

1. 把提示词发给 Codex；
2. 回答 Codex 一次一个的问题；
3. 在涉及账号、权限和最终判断时亲自确认。

Codex 会在后台检查环境、建立文件夹、运行 Starter、读取结果并处理错误。你不需要理解它使用了什么命令，但它必须把结果和阻塞翻译成人能理解的话。

如果课前软件没有准备好，Codex 应该准确告诉你缺什么，然后停下来。课堂不会为了赶进度临时扩大权限，也不会把安装失败包装成 Agent 已经搭好。

---

# 开场：先看最终效果

假设你今天出去见了一个客户，或者参加了一场线下交流。

你用飞书妙记录音。录音结束后，不需要复制逐字稿，也不需要重新告诉 AI“请帮我总结”。这条录音会自动经历七步：

1. 飞书妙记完成；
2. Codex 收到新的录音事件；
3. Codex 调用你的录音处理 Skill；
4. 原始证据和整理结果进入你的本地 Markdown；
5. 飞书给你发送一份确认单；
6. 你选择确认、修改或者改分类；
7. 你的意见回到同一份记录。

你白天只管真实交流。整理、归档和提醒交给 Agent，重要判断仍然由你负责。

这就是今天要搭的第一个 Agent。

> 配图位 1：录音 Agent 完整 Loop。用一张图看清“录音进入、Agent 处理、Markdown 入库、飞书确认、人工回复、原记录更新”的完整路径。

## 为什么从录音开始

录音 Agent 适合做第一个 Agent，因为它同时具备四个条件：

- 输入真实：来自你已经发生的交流；
- 流程重复：每次都要转写、整理、分类和确认；
- 结果可检查：最终能看到一份 Markdown 和一份飞书确认单；
- 边界清楚：AI 可以整理，但不能替你确认事实、创建任务或发布内容。

## 从 AI 航海家大课带回来的四层地图

知识库解决“Agent 做事时应该知道什么”。

Skill 解决“这件事具体应该怎么做”。

Agent 解决“谁从输入负责到输出”。

Loop 解决“这件事如何持续发生、被检查和修正”。

今天就沿着这四层往下搭。

> 配图位 2：知识库、Skill、Agent、Loop 四层地图。只解释四层各自负责什么，以及它们如何连接。

# 模块一 · 知识库：给 Agent 一间自己的办公室

## 1.1 知识库不是资料仓库，而是 Agent 的 Context

AI 很聪明，但它并不知道你的录音从哪里来、你习惯怎么分类、结果应该放在哪里，也不知道哪些动作必须等你确认。

知识库的作用，就是把这些 Context 放进一个 Agent 可以持续读取的环境里。

第一次搭建只需要分清三个位置：

- Starter 程序目录：公开工具本身；
- 个人工作区：保存你的配置、Skill 和运行状态；
- Markdown 实验库：保存处理完成的录音记录。

程序可以公开，后两个位置由你本人持有。课堂先使用新的实验目录，不重构你原有的全部知识库。

> 配图位 3：三个位置与所有权。把公开程序、个人工作区和 Markdown 实验库画成三个独立空间，并明确后两者归学员本人持有。

## 1.2 第一张提示词卡：让 Codex 检查准备状态

把下面这段话发给 Codex：

> 请打开我已经下载好的 Recording Agent Starter 项目，先阅读项目规则和主讲义。全程由你在后台完成检查，不要让我打开终端，也不要把命令发给我。请告诉我哪些已经准备好、哪些还缺失；缺失时停在准确阻塞，不要自动扩大权限或安装其他东西。

Codex 应该给你一份人能看懂的检查结果，而不是一屏技术日志。

这一阶段的完成标准只有三个：

- 软件准备状态说清楚；
- 三个位置说清楚；
- 尚未发送飞书消息或碰真实录音。

## 🙌 实操一：认清你的三个位置

和旁边的伙伴互相说清楚：

1. 哪个目录是公开程序；
2. 哪个目录保存个人规则和状态；
3. 哪个目录保存最终录音记录。

如果说不清，就继续问 Codex。不要跳到真实飞书。

---

# 模块二 · Skill：把统一方法改成你的方法

## 2.1 Skill 是一套稳定的办事方法

没有 Skill 时，你每次都要重新解释：去哪里拿录音、怎么分类、放到哪里、哪些东西值得留下。

有了 Skill，Agent 每次会按同一套方法处理，也知道什么不能做。

别人的 Skill 可以参考执行逻辑，但不能直接复制。真正需要个性化的是四件事：

### 录音来源

你的长期录音主要从哪里来？本次 Starter 的真实入口是本人飞书妙记。

### 分类体系

你未来会在哪些场景调用这些录音？第一次只保留二到五个真实分类，不提前设计庞大体系。

### 入库位置

整理后的唯一主记录放在哪里？课堂先进入新的 Markdown 实验库。

### 沉淀规则

哪些内容必须留下？至少保留原始证据、AI 整理、候选行动、人工确认和来源信息。

## 2.2 第二张提示词卡：让 Codex 一项项问你

把下面这段话发给 Codex：

> 请带我把录音处理 Skill 改成适合我的版本。依次确认录音来源、分类体系、入库位置和沉淀规则，一次只问我一个问题。确认完成后，由你创建隔离的 Starter 工作区和 Markdown 实验库，但不要发送飞书消息，不要碰我已有的正式知识库。

Codex 不能一次抛给你一张长表，也不能替你猜分类。一次只确认一个问题，确认后再进入下一项。

## 2.3 Skill 在真实使用中长出来

第一次不用追求完美。先跑一条真实录音，再观察：

- 有没有经常出现但无法分类的内容；
- AI 是否总把讨论误写成决定；
- 哪些字段你从来不用；
- 哪些重要来源没有保留。

这些真实偏差，才是下一次修改 Skill 的依据。

## 🙌 实操二：完成个人 Skill

两人互检四件事：

- 来源是否真实；
- 分类是否来自自己的生活或业务；
- 入库位置是否由本人持有；
- 沉淀规则是否保留原始证据和人工确认。

# 模块三 · Agent：让 Skill 真正开始工作

## 3.1 Skill 是能力，Agent 是负责人

Skill 像一份办事手册。Agent 则像一个负责把事情做完的人。

本次录音 Agent 的岗位可以这样描述：

- 角色：个人录音整理员；
- 触发：新的本人飞书妙记生成；
- 输入：本人妙记、逐字稿和个人录音 Skill；
- 流程：找到录音、等待完整来源、整理、写入、发送确认；
- 输出：一份唯一主记录和一份确认单；
- 边界：不自动创建任务、不发布、不删除原录音，拿不准就停。

## 3.2 先在沙盒试岗

真实 Agent 不应该第一次上班就接触你的客户资料和私人录音。

Starter 自带一条公开安全样本。它只用来验证 Agent 是否会按规则做事，不读取真实飞书，也不发送消息。

## 3.3 第三张提示词卡：让 Codex 跑安全沙盒

把下面这段话发给 Codex：

> 请在刚创建的隔离环境中替我运行安全样本，并重复运行一次检查去重。不要让我操作终端。最后只向我报告：生成了几份主记录、第二次是否重复、原始证据和 AI 整理是否分开、是否发生过任何飞书外部写入。安全样本通过不等于真实 Loop，请明确区分。

安全沙盒只有同时满足下面四项才通过：

- 只生成一份主记录；
- 第二次执行没有复制第二份；
- 原始证据、AI 整理、候选行动和人工确认分开；
- 没有任何飞书外部写入。

## 🙌 实操三：检查第一份作品

打开 Codex 给出的记录位置，和同伴检查：

- 原始内容有没有被 AI 整理稿替代；
- 没说清的负责人、时间和验收标准是否写成“未明确”；
- 是否留下人工确认位置；
- 重复运行后是否仍然只有一份。

看到安全样本不等于完整 Agent。它只证明方法和本地写入可用。

---

# 模块四 · Loop：让录音结束后自动开始

## 4.1 一次成功不等于 Loop

完整 Loop 还要解决：

- 新录音什么时候进入；
- 逐字稿没准备好怎么办；
- 同一条录音会不会处理两次；
- 结果发给谁确认；
- 人的修改能不能回到原记录；
- 服务重启后能不能继续。

实时事件是主入口。每天一次补漏只是为了找回漏掉的事件，不需要高频扫描全部录音。

## 4.2 真实启动前的五道门

进入真实飞书前，Codex 必须核对：

1. Codex、飞书工具和 Bridge 已经准备好；
2. 使用的是学员本人持有的飞书应用和授权；
3. 确认单只发给本人或明确的私人测试群；
4. 第一条录音没有客户、隐私或商业秘密；
5. 任何外部写入都先展示目标，再由本人允许。

任何一项不满足，就停在沙盒层。今天不强行跑真实录音。

## 4.3 第四张提示词卡：让 Codex 带你跑真实 Loop

把下面这段话发给 Codex：

> 请带我验收第一条真实飞书录音 Loop，全程由你在后台执行，不要让我打开终端。先检查 Codex、飞书授权、Bridge、确认目标和回复路由；把确认目标与发送身份展示给我。只有全部通过并且我明确允许发送一份测试确认单后，才启动真实链路。然后等我录制一条 45 到 90 秒的安全飞书妙记，核对实时事件、唯一 Markdown、唯一确认单和重复事件不重复处理。最后让我自己选择确认、修改或分类中的一项回复，并验证它更新的是同一份记录。任何一步没有真实证据，就告诉我准确卡点，不要宣布完整跑通。

## 4.4 这里必须由人完成的动作

Agent 可以处理技术步骤，但下面三件事不能替你做：

- 在飞书官方页面批准本人账号授权；
- 确认测试消息发给哪个本人会话；
- 决定最终是确认、修改还是改分类。

这些不是自动化缺陷，而是责任边界。

## 4.5 录制第一条真实录音

准备一条四十五到九十秒的安全录音，标题明确，不含客户、账号、私人关系或商业秘密。

可以围绕三个内容说：你正在测试什么；你希望 Agent 产出什么；还有什么尚未明确。

录音结束后，不要手动复制逐字稿。等待 Codex 检查实时事件。

## 4.6 真正完成的证据

只有下面五项都成立，才叫完整闭环：

- 新妙记由实时事件进入；
- 本地只新增一份主记录；
- 飞书只收到一份确认单；
- 同一事件再次出现时不重复处理；
- 你的飞书回复更新了同一份记录。

如果只完成前三项，叫“处理链已通，人工回写待验证”。不要把它说成完整 Loop。

> 配图位 4：三层验收证据。区分安全沙盒、真实处理链和人工回写闭环，明确每一层需要看到什么证据。

## 4.7 失败时怎么处理

Codex 应该把失败归到准确的一层：

- 软件缺失：回到课前准备；
- 授权未完成：只完成官方授权，不扩大其他权限；
- 逐字稿未准备好：只等待当前录音；
- 事件漏掉：得到允许后只补这一条或这一天；
- 确认目标不唯一：停止发送；
- 回复对象或分类不明确：请求澄清；
- 网络不稳定：切回安全沙盒，不伪装实时成功。

一个问题卡住五分钟仍无进展，就记录准确阻塞并继续课程。准确知道卡在哪里，也是一份有效结果。

## 🙌 实操四：跑第一条真实录音 Loop

绿灯组使用第四张提示词卡，按 Codex 的节奏完成。

跟做组继续完善个人 Skill 和安全样本，明确真实 Loop 还缺哪一门。两组都不共享飞书凭证，也不使用讲师的机器人替学员完成。

# 收尾：四句话带走整套系统

1. 知识管理正在变成 Context 管理，重点是 Agent 能否拿到正确的信息。
2. Skill 是稳定的办事方法，必须根据自己的来源、分类、位置和规则个性化。
3. Agent 是对一段完整结果负责的角色，不是堆很多工具名称。
4. Loop 是可以持续纠正的工作，人的反馈要回到同一系统。

今天的完成，不是“我听懂了 Agent”。

而是你已经拥有自己的录音 Skill、一份唯一安全样本，或者一条由真实飞书录音触发并回到本人确认的 Loop。

先让一条录音真正闭环，再搭第二个 Agent。

本轮先确定图片要表达的事实，不做 PPT，不加装饰图。每张图都必须帮助学员看清一个容易混淆的关系。

## 图 1 · 录音 Agent 完整 Loop

必须强调两点：学员全程只和 Codex、飞书交互；人的回复回到同一份记录，不另起一套待办系统。

## 课后 72 小时行动

离场前，在活动群里说明：

- 我今天真实完成了什么；
- 我的录音 Agent 现在停在哪一层；
- 我会在七十二小时内完成什么可检查动作；
- 我想请哪位伙伴帮我互检。

只选一个下一步：完成准备、完成 Skill、跑通安全样本、让真实检查全绿，或者闭合第一条真实妙记。

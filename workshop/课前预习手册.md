# 8 月 3 日线下分享｜课前预习手册

> 活动主题：从一条录音开始，用飞书 + Codex 搭建你的第一个录音 Agent
>
> 活动时间：2026 年 8 月 3 日 14:00–16:00
>
> 建议准备时间：45–90 分钟；首次飞书扫码绑定可能需要更久

欢迎参加这次线下分享。

现场只有两个小时。我们希望把时间留给真正的实操：把录音处理方法改成你的、跑通第一条录音 Agent Loop，而不是临时安装软件。

所以课前只做一件事：**先让 Codex 帮你把电脑准备到“安装就绪”。** Node、官方飞书
CLI、Local Channel Bridge、本人 Bridge Profile 和课程测试包都应在课前完成；现场不再从零
安装这些基础设施。

你不需要学习安装命令，也不需要打开终端。能交给 Agent 的准备工作，都通过下面的提示词交给 Codex；只有软件下载、账号登录和系统授权等必须由本人完成的动作，才需要你手动操作。

---

## 一、课前请记住 4 件事

### 1. 先完成预习，再来现场

“已经下载”不等于“已经准备好”。软件能打开、账号能登录、Agent 完成检查并给出结果，才算准备完成。

### 2. 把 Agent 当成你的课前助教

遇到不懂的名词、安装失败或报错，不用自己搜索一堆教程。把页面或报错交给 Codex，让它先用大白话解释，再一次只处理一个问题。

### 3. 必须由你本人完成的动作，不交给 Agent 代替

请亲自完成：账号登录、系统弹窗授权、飞书授权确认、选择自己的文件夹，以及最后是否继续的决定。

不要把密码、验证码、token、secret、客户录音或私人妙记链接发到活动群。

### 4. 卡住超过 15 分钟，带着准确反馈来问

不要只说“装不上”。请让 Codex 告诉你：卡在哪一步、准确原因是什么、已经尝试过什么、下一步需要谁来做。

---

## 二、先手动准备 2 个软件

这两个软件必须先由你本人下载、打开并登录。完成后，后续准备工作才能继续交给 Agent。

### 1. Codex

作用：本次活动中与你对话、检查环境、安装后台依赖、运行 Starter 和排查问题的主要 Agent。

- 官方页面：[OpenAI Codex](https://openai.com/codex/)
- 请从官方页面下载并安装适合你电脑的版本；
- 打开 Codex，用自己的 ChatGPT 账号登录；
- 新建一个对话，确认可以正常发送和收到回复。

如果 Codex 还不能正常对话，请先解决这一步，不要继续往下。

### 2. 飞书

作用：录制飞书妙记，并在后续真实 Loop 中接收录音 Agent 的确认单。

- 官方页面：[飞书下载](https://www.feishu.cn/download)
- 安装飞书桌面端并登录；
- 请使用活动当天准备继续使用的同一个飞书账号；
- 打开一次“飞书妙记”，确认页面可以正常使用。

本次课前不要求安装 Hermes，也不要求提前接入真实客户录音。我们先用飞书 + Codex + Recording Agent Starter 跑通最小闭环。

---

## 三、第一张提示词卡：安装完整课堂环境

完成上面两个软件的手动准备后，把下面整段话复制给 Codex：

```text
我要参加 8 月 3 日的录音 Agent 线下分享。请帮我把这台 macOS 电脑准备到“安装就绪”。全程由你在后台完成检查和必要安装，不要让我打开终端。

本课程锁定并验证过的基础环境是：
- Node.js >= 20.12；
- 已安装并登录的 Codex CLI；
- 官方 @larksuite/cli / lark-cli 1.0.81；
- lark-channel-bridge 0.6.4；
- 本人持有的 Bridge Profile：RecordingAgentCourse，agent 使用 codex。

只允许使用以下来源：
- 官方飞书 CLI：https://github.com/larksuite/cli
- Local Channel Bridge：https://github.com/zarazhangrui/feishu-claude-code-bridge
- Bridge npm 包：https://www.npmjs.com/package/lark-channel-bridge

请按顺序处理，一次只处理一个缺项：
1. 检查 node、npm、codex、lark-cli、lark-channel-bridge 的实际可执行路径和版本，防止“装过但当前 Codex 的 PATH 看不到”。
2. 如果官方 lark-cli 缺失、低于课堂基线，或没有 event / minutes / api / auth status 命令，使用官方安装器 `npx @larksuite/cli@1.0.81 install` 安装或更新。不要安装 npm 上无 scope 的同名 `lark-cli` 包；它不是本课程使用的官方 CLI。高于课堂版本时不要静默降级，能力检查通过即可保留。
3. 如果 Bridge 缺失、低于课堂基线，或没有 profile / start / status 命令，使用 `npm install --global lark-channel-bridge@0.6.4` 安装或更新。高于课堂版本时同样先做能力检查，不要静默降级。
4. 先运行 Bridge profile 列表。如果 `RecordingAgentCourse` 不存在，创建该 Profile，agent 选择 codex。首次创建会出现飞书二维码：把二维码展示给我，停下来由我本人扫码、创建或绑定我自己的 PersonalAgent。不要使用讲师或其他学员的 Profile、app secret、token 或飞书应用配置，也不要让我把 secret 发到聊天中。
5. 绑定完成后，把该 Profile 启动为系统后台服务，并核对 profile list 和 status 能确认 `RecordingAgentCourse` 存在、agent=codex、服务正在运行。
6. 最后重新检查：`lark-cli --version`、`lark-cli event --help`、`lark-cli minutes --help`、`lark-cli api --help`、`lark-cli auth status --help`、`lark-channel-bridge --version`、Bridge Profile 和后台服务状态。

需要下载安装前，先用一句话告诉我“要安装什么、为什么需要”；遇到账号登录、二维码、管理员密码、系统权限或飞书授权时必须停下来让我本人完成。允许在我确认后启动 `RecordingAgentCourse` Bridge 后台服务；但这一阶段不要读取真实录音、不要发送飞书消息、不要安装录音 Hook、不要修改飞书文档权限或扩大机器人可见范围。

最后请用四栏回复：
1. 已安装：实际路径、去敏版本和能力检查结果；
2. Bridge：Profile 名、agent 类型和服务状态，不输出凭证；
3. 需要本人确认：尚未完成的扫码、登录或权限动作；
4. 当前阻塞：准确卡点和唯一下一步。

只有工具齐全、`RecordingAgentCourse` 已属于我本人并正常运行，才能写“安装就绪”。不要因为还没读取真实妙记就判定安装失败。
```

你只需要跟着 Codex 一次回答一个问题。它要求你确认登录或系统授权时，再由你亲自操作。

## 四、第二张提示词卡：让 Agent 准备课堂项目

第一张提示词卡完成后，继续把下面这段话发给同一个 Codex 对话：

本次活动使用 `v0.2.0-beta.2` 课程测试包。它已经公开发布，但仍标记为 Pre-release，不能说成稳定版。愿意参加课程测试的同学再继续这一步；如果不希望使用预发布版本，完成第一张提示词卡后停下并告诉组织者即可。

```text
请打开 Recording Agent Starter v0.2.0-beta.2 的官方 Release 页面：
https://github.com/kellanxu/recording-agent-starter/releases/tag/v0.2.0-beta.2

请先核对：页面版本确实是 v0.2.0-beta.2，标记为 Pre-release，并且 Release 说明明确采用“接入 Bridge Hook、复用唯一长连接”的课程架构。如果不一致，请停止并告诉我准确差异。

开始前先复查第一张卡的安装结果：官方 lark-cli 具备 event / minutes / api 能力，`RecordingAgentCourse` Bridge Profile 存在且服务运行。任一不满足就返回第一张卡修复，不要跳过。

确认无误后，只下载这两个 Release 资产：
1. recording-agent-starter-0.2.0-beta.2.zip
2. recording-agent-starter-0.2.0-beta.2.zip.sha256

不要下载 GitHub 自动生成的 Source code。请在后台完成 SHA-256 校验；校验失败就停止，不要继续安装。

校验通过后，安装 ZIP 中已经构建好的 `recording-agent` 本地命令。为课堂新建一个隔离的 Starter 工作区和一个 Markdown 实验库，不要碰我已有的知识库，也不要读取真实飞书录音。

初始化时把 Bridge Profile 明确设为 `RecordingAgentCourse`。录音来源、分类体系、入库位置和沉淀规则一次只问我一个问题；课前不配置真实确认目标，不发送消息。

然后由你在后台完成项目检查，连续运行两次安全 sample，验证第二次不会产生重复记录。全程不要让我打开终端，不要发送飞书消息，也不要启动真实录音 Loop。

最后只告诉我：下载的版本、SHA-256 是否通过、`recording-agent` 是否可用、Workspace 是否明确绑定 `RecordingAgentCourse`、doctor 的依赖能力检查、生成了几份主记录、第二次是否重复、原始证据和 AI 整理是否分开、是否发生过任何飞书外部写入。请明确说明：这是课程测试版；安全 sample 通过，不等于真实飞书 Loop 已经跑通。
```

这一阶段使用的是公开安全样本，不需要你提供自己的真实录音。

## 五、第三张提示词卡：让 Agent 做最终验收

前两步完成后，再发送：

```text
请对照 8 月 3 日线下分享的课前目标，做一次最终验收。不要继续安装新工具，也不要启动真实录音 Loop。

请按下面格式回复：
1. 安装就绪：Node、Codex、官方 lark-cli、Bridge、本人 Profile、Bridge 服务和 recording-agent 的实际状态；
2. 需要本人确认：仍需我登录、授权或选择的项目；
3. 当前阻塞：准确卡点、原因和唯一的下一步；
4. 课程包：是否为 v0.2.0-beta.2，SHA-256 是否通过；
5. 安全证据：两次 sample 是否只生成一份记录，是否没有飞书外部写入。

只有以下条件全部成立才写“课前安装完成，可以参加现场实操”：
- lark-cli 和 Bridge 均可执行且具备课程要求的命令能力；
- `RecordingAgentCourse` 是本人扫码绑定的 Profile，agent=codex，后台服务运行；
- Starter 课程包和 recording-agent 已安装；
- 两次安全 sample 只生成一份记录，且没有飞书外部写入。

真实妙记读取授权、确认目标、录音 Hook 和测试消息仍留到现场，不把它们写成课前安装失败。如果安装项未完成，请不要模糊地说“应该可以”。
```

看到“课前安装完成，可以参加现场实操”，课前准备才完成。

真实飞书授权、确认单发送和自动触发，会在现场由 Codex 带着你逐项确认。课前不需要为了追求“全绿”而扩大权限。

## 六、遇到问题时，用这张求助卡

如果 Codex 反复失败，先把下面这段话发给它：

```text
不要继续重复安装，也不要换一堆方案。请用大白话告诉我：准确失败在哪一步、最可能的原因、你已经尝试过什么，以及我现在唯一需要做的下一步。如果需要账号、权限或管理员确认，请停下来等我，不要代替我决定。
```

仍未解决时，把 Codex 的这四项反馈发给小组长或带到现场即可。发送前请检查并遮住密码、验证码、token、secret、私人路径和真实录音内容。

- [ ] 已带笔记本电脑和电源；
- [ ] Codex 已安装、已登录，并能正常对话；
- [ ] 飞书桌面端已安装、已登录，并能打开飞书妙记；
- [ ] 官方 lark-cli 已安装，并通过 event / minutes / api / auth status 能力检查；
- [ ] lark-channel-bridge 已安装；
- [ ] 本人已扫码创建或绑定 `RecordingAgentCourse`，agent=codex，后台服务运行；
- [ ] Agent 已回复“课前安装完成，可以参加现场实操”；
- [ ] Agent 已确认课程包为 `v0.2.0-beta.2`，并且 SHA-256 校验通过；
- [ ] 两次安全 sample 只生成一份记录；
- [ ] 已准备一个 45–90 秒、不含隐私的安全录音主题，现场再录制；
- [ ] 如果仍有卡点，已经保存 Codex 给出的准确阻塞说明。

完成这些就够了。现场我们会继续把统一的录音处理 Skill 改成你的方法，再由 Agent 带你跑第一条真实录音 Loop。
